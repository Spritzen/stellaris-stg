# Star Trek Galaxies

A total-conversion Stellaris mod, built by vendoring 49 Workshop mods into one
standalone tree. Target: **Stellaris 4.4.x "Pegasus"**
(`modsCompatibilityVersion` 4.4).

The built mod lives in **`stg-build/`** — the game's directory layout (`common/`,
`events/`, `localisation/`, `gfx/`, `interface/`) plus `descriptor.mod`, all of it
GENERATED by `make vendor`. The repo root holds the inputs: `vendor.yml`, `src/`,
`tools/`, `.source/`. **The repo root is not the mod root**
([decision 12](.docs/decisions/12-build-dir-and-symlink-deploy.md)).

## The four invariants

These are the ones that cost a session when they are missed. Full form, with the
lever for each: [.docs/guides/working-rules.md](.docs/guides/working-rules.md).

1. **STG is standalone.** It vendors its own copy of every source mod. There is
   no load order to lean on at runtime — the merge is resolved at build time, in
   harvest order.
2. **Never hand-edit a vendored file.** Anything under `stg-build/` comes from a
   source mod. Change it through `src/`, a `patches:` entry, a `renames:` entry
   or `resample_to_vanilla:` in `vendor.yml`. A silent edit is lost on the next
   `make vendor` and invisible in review.
3. **The build reads `.source/`, never `/workshop`.** `make sources-sync` is the
   only thing that touches `/workshop`, and it is a deliberate act. `.source/` is
   a mirror — never hand-edit it either.
4. **Fix a source mod's errors; never drop the mod to silence them.** A source is
   dropped only on **content** grounds, never by quoting an error count
   ([decision 11](.docs/decisions/11-fix-source-errors-dont-drop.md)).

## The daily loop

```bash
make vendor      # rebuild stg-build/ from .source/ + src/, then prune
make validate    # structure + whether every name resolves against the merge
make docs        # every doc link and code citation resolves
```

The mod folder is a **symlink** to `stg-build/`, so a rebuild is live the moment
it finishes. `make link` is needed once.

Run `make validate` after any script edit, `make clutter` after any change to
what is harvested, `make docs` after any change to documentation.
[All targets](.docs/guides/workflow.md).

**Finished work is committed straight to `main` and pushed to `origin`** — no
feature branch, no PR. This is a single-maintainer repo with no review step to
serve, so a branch adds ceremony without adding a reader. **"Commit" here always
means commit *and* push**; work that is only local is not delivered. Wait to be
asked, and run the loop above first: with nothing else gating what lands, it is
the only gate.

## Four things about this environment

Full detail: [.docs/guides/environment.md](.docs/guides/environment.md).

- `/stellaris` (read-only) is vanilla — **the reference for everything**.
  `/workshop` (read-only) is Steam's mods. `/paradox/stellaris` (read-write) is
  live user data: the deploy target, the launcher database, `logs/error.log`.
- **Never write to `/stellaris` or `/workshop`.**
- **Before writing script, read vanilla.** Guessing at effect, trigger or scope
  names produces files the game silently drops. Ground every change in a real
  vanilla example you actually opened
  ([how](.docs/guides/writing-script.md#before-writing-script-read-vanilla)).
- **The game runs on the host.** Container-side you validate structure, never
  behaviour. Say "validates clean" and stop — **but when the user reports a live
  run, read `/paradox/stellaris/logs/error.log` before saying anything about how
  it went** ([procedure](.docs/guides/live-runs.md)).

## When you resolve something

Write `.docs/decisions/NN-slug.md`, add its row to
[the index](.docs/decisions/README.md), and update
[status.md](.docs/planning/status.md) and
[open-questions.md](.docs/planning/open-questions.md) if it closes something they
list. Format: [style guide §7](.docs/style-guide.md#7-decision-files-have-a-fixed-head).

**A stale document is worse than none.** When you find one contradicted by what
is on disk, fix it — that is part of the task, not a digression.
